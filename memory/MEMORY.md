# 記憶の索引（MEMORY.md）

セッション開始時に読む索引。1記憶=1ファイル。ここには1行ずつのポインタだけ書く。
（出典: ループエンジニアリングの memory システムを PachiTracker 運用に移植）

- [リプ周り・返信の学習](feedback_reply_outreach.md) — パチンコ用語/当たりの良し悪しを事実確認してから返信。嘆きにおめでとう厳禁。閉じた会話は無理に開けない。当たり前の質問・説明NG（相手が知ってる演出を解説し返さない、2回再発）。期待値稼働勢は「回ってれば打つ」が大前提、出玉/当たりの質での続行判断は聞かない（2回目再発）。**候補全体がインタビューっぽく硬い→質問は毎回つけない、短く崩す、引用→共感→質問のテンプレ順を毎回使わない。** 確認済み用語集あり。
- [投稿フォーマットの学習](feedback_post_format.md) — 型・禁止表現・positioning の逸脱メモ（正典は prompts/）。
- [検証・事実確認の学習](feedback_verification.md) — それっぽい穴埋め禁止。曖昧なら「未確認」と書くか本人に聞く。

## 運用ルール

- **同じ修正・指摘を2回受けたら** `feedback_◯◯.md` に追記し、ここに索引を1行足す。
- 記憶が増えるほどループは賢くなる（＝放置・自走できる範囲が広がる）。
- 記憶は「やってはいけない理由(Why)」と「次にどう適用するか(How)」をセットで書く。
