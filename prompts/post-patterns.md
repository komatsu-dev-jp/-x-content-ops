# Post Patterns

## 文体ルール（必須・全型共通）

**禁止**: 「気づけば、〜している。」「全部、〜が決めている。」のように、毎回きれいな一文でオチ・警句をつけて締める書き方。
これは川柳・詩っぽくなり「AIが書いた文章」に見える。人が思わずつぶやいた投稿に見えるようにする。

具体的にやること:

- 語尾に口語を混ぜる（〜んですよね／〜なって／〜してます／〜けど／〜し／〜かも）。「です・ます」だけで揃えない。
- 一文の長さをわざと不揃いにする。短い断定＋長めの説明、のように崩す。
- 毎回「だから〜しています」で締めて製品接続しなくていい。PachiTrackerへの言及は会話の流れの中で自然に挟む（触れない投稿があってもよい）。
- 「〜すり替わっている」「〜がサイン」のような評論家的な言い回しを避け、「〜なんですよね」「〜だったな」のような一人称の実感で書く。
- 体言止め・対句（AとBを綺麗に並べる）を多用しない。1投稿1箇所まで。

チェック方法: 声に出して読んで、知人にLINEで送るときの言い方になっているか確認する。ならなければ書き直す。

## 1. 問題提起型

目的：共感、返信、プロフィール遷移。

構造（例）：

```text
撤退の判断を決めてても、座ると「もう少しだけ」で結局溶かす。

自分もこれで何度もやられてて、気づいたら続ける理由が最初のやつと
すり替わってるんですよね。

だから続ける理由、その場で記録に残すようにしてます。
```

## 2. あるある型

目的：軽い拡散、読者の自分事化。

構造（例）：

```text
これ、正直自分もやる。

・昨日出ていた台に座る
・前半回った記憶でそのまま続ける
・投資したからヤメられない

判断が歪んでるだけなんだけど、その場だと気づかないんですよね。
```

## 3. 失敗告白型

目的：人間味、信頼、開発者感。

構造（例）：

```text
自分で記録アプリを作ってるのに、記録サボって判断ミスしたことあります。

だから、入力はもっと軽くする必要があるなと。

便利な機能より、続く設計を優先してます。
```

## 4. UIスクショ型

目的：プロフィール遷移、プロダクト理解。

構造（例）：

```text
入力が面倒だと、正しい判断より「楽な判断」を選んじゃう。

だからPachiTrackerは、実戦中に迷わず押せる導線を優先しました。
```

## 5. 検証メモ型

目的：信頼、保存、リポスト。

構造（例）：

```text
感覚で「回ってる」と思った台ほど、あとで記録見るとブレてること多い。

記憶じゃなくて数字で振り返る癖、つけたいんですよね。
```

## 6. β募集型

目的：見込みユーザー獲得。

構造（例）：

```text
台選び・続行・撤退を、
感覚じゃなくて記録で見直したい人へ。

β版は少人数から、ぼちぼち始めようと思っています。
PachiTrackerってアプリを作ってます。

興味あれば、リプかDMで教えてください。
```

## Hook Bank

- 台選びを勘でやると、あとで話す内容が毎回変わるんですよね。
- 勝った日の記憶だけ残るの、正直かなり危ない。
- 入力が面倒だと、正しい判断より「楽な判断」を選んじゃう。
- 自分用に作った記録アプリ、一番離脱してたの自分でした。
- β版、便利機能を増やしたら逆に使いづらくなって焦りました。
- パチンコの反省、感情で振り返ると毎回ズレるなと思う。
- 「残した数字」と「頭の中の印象」が合ってない瞬間、地味に怖い。
