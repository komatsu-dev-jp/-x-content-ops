# /loop プロンプト集 — PachiTracker X運用版

Claude Code の `/loop` に貼って使う実戦テンプレ。`<<...>>` を環境に合わせて書き換える。
（出典: ループエンジニアリングのテンプレを PachiTracker 運用に移植）

良いループの条件4つ: **何を（ゴール）／どのSkillで／どう検証して／いつ終わるか（終了条件）** が全部入っていること。

> **いつ /loop を使うか（結論：普段は不要）**
> 日常運用は単発でSkillを呼べば回る（毎日 `/x-reply-outreach`、日曜 `/x-growth-company` と `/x-weekly-review`）。
> `/loop` は「同じ作業を複数回、自動で連続実行したい」時だけ。実質の使いどころは **日曜の週次投稿バッチ（下の1）** くらい。
> 曜日別の運用手順の正本はNotion「🧭 X運用の使い方＆Skill早見表」ページ。

> **公開境界（厳守）**: どのループも「生成・分析・下書き保存まで」。Xへの投稿・返信送信・コミット/プッシュは人間が承認して行う（`CLAUDE.md`）。

---

## 0. ★日曜の週次エンジン（最重要・これ1本で週の準備が完結）★

週で唯一の重い頭脳作業（振り返り→仮説→backlogから投稿5本→採点→予約準備）を **/goal 1本に束ねる**。
`/loop` ではなく `/goal` を使う理由は「score90以上の投稿が5本揃う」という明確な終了条件があるから。
**普段使う自動化はこれだけでOK。** 日曜に1回流し、出力を最後に目視レビューする。

```
/goal
来週分のPachiTracker X投稿を「予約できる状態」まで一気に仕上げる。

手順:
1. npm run weekly を実行し x-weekly-review で解釈。勝ち仮説を1つだけ出し ab_test_plan.csv に反映
2. reply_outreach_log.csv で got_reply=1 だが follow が空欄の相手を確認し、
   自分のフォロワー一覧と照合して follow=1/0 を更新する（週次でこのチャネルの転換率を必ず把握する）
3. npm run backlog -- --status で未使用ネタを確認。来週の投稿は「まず backlog の未使用から引く」
   （ゼロから考えず在庫を使う。足りない角度だけ x-idea-harvest で補う）
4. 引いたネタと仮説・型×時間帯ローテに沿って x-growth-company で投稿を5本生成
5. 各案を x-score-post と x-risk-check にかけ、score90以上 / risk none になるまで直す
6. **投稿日は月・水・金の3枠だけに割り当てる**（曜日別ルーティンの正典。毎日投稿にしない。
   金曜は5本中いちばん強い1本）。残り2本は「翌週在庫」として翌週の月・水に仮置きする
7. 使ったネタは npm run backlog -- --consume "idea前方一致" post_id=... で投稿済にする
8. 未使用が10件を切っていたら x-idea-harvest で15件まで補充
9. npm run schedule で予約用CSVを output/ に書き出す

達成条件: 5本が score90↑ / risk none / 月水金3本+翌週在庫2本に割当済み / CSV出力済み /
　　　　　backlog消化と補充が済んでいる / リプ周りのfollow追跡が更新済み
達成したら要約を出して停止。公開・コミットはしない（人間が確認）。
```

> backlogは「溜める→使う→補充」を回して初めて機能する。この/goalが**消化と補充を毎週自動で回す**ので、
> あなたは平日に思いついたネタを1行足すだけ（`npm run backlog` で在庫確認、または私に言う）。

## 1. 週次投稿バッチだけ回したい時（軽量版）

```
/loop
x-growth-company を使って、来週のPachiTracker用X投稿候補を5本作って。

- まず backlog の未使用ネタ（npm run backlog -- --status）から引く。足りない角度だけ新規で足す
- 切り口は5角度（記憶のズレ/入力の面倒さ/続行理由/店・台選び/UI思想）から分散させる
- 各案に score / risk / 推奨タイムスロット / CSVログ用メモ を付ける
- banned-patterns と scoring-rubric のセルフチェックを必ず通す
- 使ったネタは投稿済にマーク（npm run backlog -- --consume ...）
- 最大5本できたら output/ に保存してレポートを出して停止
公開はしない（人間が選んで手動投稿）。
```

## 2. ネタ補充（backlogの未使用が10件を切った時だけ）

```
/loop
x-idea-harvest を使って、idea_backlog.csv の未使用ネタを15件になるまで補充して。

- npm run backlog -- --status で現在の未使用数を確認してから始める
- 既存ネタ（投稿済も含む）と重複しないこと。角度が偏らないこと
- 1件ずつ「痛点 / 角度 / 想定型」を付け、status=未使用 で追記
- 15件に達したら停止
```

## 3. リプ周り準備（開いてる投稿を見抜いて返信案を作る）

```
/loop
渡す投稿（リンク or 本文）について x-reply-outreach で返信案を3つ作って。

- まず「会話が開いているか（迷い・問い・愚痴か）」を判定。閉じていれば返信非推奨と理由を述べる
- パチンコ用語・当たりの良し悪しは確証がなければ確認する（memory/feedback_reply_outreach.md）
- リンク・宣伝は入れない
返信案を出したら停止。送信は人間が行う。
```

## 4. 週次レビュー → 学習（改善ループ）

```
/loop
npm run weekly の結果（data/post_log.csv）を x-weekly-review で解釈して。

- 最低母数・経験ベイズ縮小・交絡を踏まえ、「勝ち仮説」を1つだけ出す
- 同じ改善指摘が2回出ていれば memory/feedback_*.md に追記し MEMORY.md に索引を足す
- 来週のA/B変数（1つだけ）を data/ab_test_plan.csv 方針に沿って提案
分析→記録→次週仮説まで出したら停止。
```

> 週次レビュー単体（4）は日曜の週次エンジン（0）に内包済み。切り分けて回したい時だけ使う。

---

## 使い分けの結論

| 頻度 | 手段 |
|---|---|
| 毎日（リプ周り） | 単発 `/x-reply-outreach`。**loop化しない**（あなたの入力待ちで止まるだけ） |
| 週1（日曜） | **`/goal` 週次エンジン（0）** — 振り返り〜投稿5本〜backlog消化まで1本で |
| 随時（ネタ切れ） | `/loop` ネタ補充（2）— 未使用が10件を切った時だけ |

## アレンジのコツ

- 動かないときはまず「ゴールが曖昧でないか」を疑う（×「投稿がんばって」→ ◯「候補5本をscore90で下書きまで」）。
- 検証項目を1つ足すごとに、放置できる時間が伸びる。
- 公開・課金・削除・プッシュは必ず「人間に確認してから」と書く。
